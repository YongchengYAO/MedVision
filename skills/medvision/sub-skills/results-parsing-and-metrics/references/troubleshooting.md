# Troubleshooting: parsing and summarizing

| Symptom / error fragment | Likely cause | Fix / validation | Stop when |
|---|---|---|---|
| `FileNotFoundError: .../parsed/summary_metrics_*_Task.json` during the report step, or `Parsed files directory does not exist ... skipping` followed by a crash | a model folder under `--task_dir` has no `parsed/` (never parsed, or a non-model folder such as a backup) | add `--skip_model_wo_parsed_files`, or restrict with `--models <roster>`; parse the missing model first | never blocks |
| `[FATAL] <file> has no 'filtered_resps' key ... keys present: ['LLM_filtered_resps', 'resps']` | summarizing an `llm-parsed_<judge>/` folder without `--resps_key` (`assert_resps_key`) | add `--resps_key LLM_filtered_resps`; conversely drop `--parsed_dirname` to summarize `parsed/` | never blocks |
| `KeyError: ... has no 'filtered_resps'; this directory mixes record schemas` | a folder mixing judge records and regex records | keep one schema per folder; re-run the judge step for the whole folder or delete the stray files | never blocks |
| `avgNMAE` is `nan` for every group, or `nMAE` missing from parsed records | (a) parsed files predate nMAE support; (b) at parse time the NIfTI files were not at `doc.image_file` (diagonal cannot be computed, failure is silent); (c) A/D angle groups never have nMAE | (a) re-run `parse_outputs` (with `--rm_old` or without `--skip_existing`); (b) mount the data at the recorded absolute paths and re-parse, or accept NaN; (c) expected | (b) needs the dataset images (large download) |
| `--limit 100` summary counts do not match what is on disk | `--limit` takes the FIRST N lines per parsed file (parse: lowest `doc_id`s) and, for TL, removed slices still count toward N | for a fair 100-sample comparison parse and summarize both trees with the same `--limit`; check counts with `scripts/inspect_summary.py --path <parsed dir>` | never blocks |
| `ModuleNotFoundError: No module named 'medvision_ds'` (also from `parse_outputs`), `... 'torch'`, `... 'transformers'` | `parse_outputs` and the summarizers import the vendored eval utilities, which import these three at module level | install `medvision_ds` with `python -m medvision_bm.benchmark.install_medvision_ds --data_dir <data_dir>`; `torch`/`transformers` come with the benchmark package's requirements (CPU builds are fine); use the same interpreter for both steps (see `../../environment-setup/SKILL.md`) | needs network for the first install |
| `ValueError: Error loading benchmark plan for <dataset>, task N` | `medvision_ds` is installed but lacks that dataset module, or `DATASETS_NAME2PACKAGE` has no entry for the dataset name parsed from the file name | check the dataset name between `samples_` and the next `_` in the file name; update `medvision_ds` / the mapping (maintainer task, `../../extending-models-and-tasks/SKILL.md`) | needs a package change |
| `--removed_samples_dir` given but output has no `_filtered` effect / warnings | wrong root: it must be the folder that CONTAINS `<dataset>/multi_cluster_samples_v1.0.0_to_v1.1.0.json` (typically `<data_dir>/Datasets`); a missing file is silently treated as "nothing to remove" | check `ls <dir>/<dataset>/multi_cluster_samples_v1.0.0_to_v1.1.0.json`; pass `--removed_samples_filename` if the file is named differently | never blocks |
| Mean `IoU` (e.g. 0.62) is higher than `IoU>0.5` (e.g. 0.41) and the user suspects a bug | different quantities: `IoU` is the mean over ALL samples (failures = 0), `IoU>0.5` is the fraction of ALL samples with IoU >= 0.5; partial overlaps in (0, 0.5) raise the mean without counting as hits, and `Acc@IoU>=0.50` is the same number as `IoU>0.5` | run `scripts/metrics_demo.py`; explain with `metrics.md` section 3 (`IoU_reported = IoU_over_successes * SuccessRate`) | never blocks |
| Detection `avgMAE` looks fine but `IoU`, `F1` are near 0 | boxes answered in pixels or in the wrong corner order beyond sorting; MAE in relative units > 1 confirms pixel answers | inspect `filtered_resps` vs `target` in the parsed JSONL; this is a model-format issue, not a parsing bug | never blocks |
| `ValueError: Label '<name>' not found in label_map_regroup` (or `label_map_rename`) | a dataset label without an entry in `medvision_bm.utils.configs` (new dataset/task) | add the label to `label_map_regroup` and `label_map_rename` (maintainer task, see `../../extending-models-and-tasks/SKILL.md`) | needs a package change |
| `ValueError: Results file not found for task <ts>. Expected at: .../<ts>_results.json` | the raw JSONL lost its sibling results file, or files were renamed | restore the file from the eval run (or re-run the eval); never rename `<ts>_samples_*.jsonl` | may need a GPU re-run |
| `ValueError: Unable to determine task ID from filename` / summarizer `AttributeError: 'NoneType' object has no attribute 'group'` | file name lacks `_samples_` or `samples_<dataset>_` (renamed or foreign JSONL in the folder) | move analysis JSONLs elsewhere (`_proc_acc`/`_eq_acc` files are skipped automatically) and keep original names | never blocks |
| `AssertionError: metric_key is None in line N` (A/D) | a record without `biometric_profile.metric_key` (corrupted or non-A/D file in an A/D folder) | remove the foreign file; if the raw file is corrupt, re-run the eval for that config | may need a GPU re-run |
| Responses correct but `SuccessRate` low; `filtered_resps` is `""` | answers written outside `<answer></answer>` (`\boxed{}`, `**Answer:**`, prose) or fewer than k numbers inside the tag | this is by design for the regex pass; run the LLM-judge re-parse (`../../llm-judge-parsing/SKILL.md`) and summarize with `--parsed_dirname llm-parsed_<judge> --resps_key LLM_filtered_resps`; diff the reports | judge needs a GPU |
| Same `doc_id` several times in a raw JSONL; group counts exceed the task limit | multi-rank eval wrote duplicates | `python -m medvision_bm.benchmark.remove_duplicate_samples --dir <task_dir> --out_dir <new_dir>`, then parse/summarize the new tree; detect with `scripts/inspect_summary.py --path <model_dir>` (`dup_ids`) | never blocks |
| `-p N` slower than serial, memory pressure, or workers die without traceback | too many processes for the machine (each worker loads a whole JSONL / label group into memory; detection files are large) | use `-p` <= CPU cores and well below available RAM / per-file size; run models one at a time with `--model_dir` | never blocks |
| `PicklingError` / `AttributeError: Can't pickle local object` when calling `main(...)` from a notebook with `processes > 1` | worker functions must be importable by name; interactive redefinitions or monkeypatches break that | run the modules with `python -m ...` from a shell, or drop `-p` | never blocks |
| Task-level `summary_*_task.txt` silently lists old numbers after a re-run | the report step reads `summary_metrics_*` files left by a previous run for models it did not re-process | re-run with the same `--limit`/`--removed_samples_dir`/`--parsed_dirname` combination for every model, or delete stale summary files first | never blocks |
| `random_detection` results missing from `summary_detection_task.txt` | the detection summarizer excludes that folder by name (it is the random baseline of the box-size analysis) | intended; read it from the box-size outputs | never blocks |
| Importing `medvision_bm.benchmark.*` takes 20-60 s | the modules import the vendored eval utilities (NumPy/nibabel stack; torch when present) | expected once per process; prefer one `--task_dir` run over many `--model_dir` runs | never blocks |
| `pip install` suggested to fix an import | mutating an eval environment can break pinned model stacks (`huggingface_hub`, `transformers`) | install into a separate analysis environment, or use the environment described in `../../environment-setup/SKILL.md` | ask before mutating shared envs |

Cross-cutting issues (environment, data download, GPU) are in `../../../references/troubleshooting.md`.
