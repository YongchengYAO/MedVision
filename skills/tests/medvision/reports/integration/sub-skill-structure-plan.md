## Root (`medvision/SKILL.md`, 80-150 lines, router)
- What MedVision is: benchmark + post-training toolkit for *quantitative* medical image analysis with VLMs
  (Detection = bounding box, T/L = tumor/lesion size in mm, A/D = angle/distance from landmarks), package
  `medvision_bm` (PyPI `medvision-bm`, CLI `mvbm`), sibling dataset package `medvision_ds`, HF dataset
  `YongchengYAO/MedVision`, model MedVision-V0-7B.
- Install + minimal import check; `mvbm install mvds -d Data`; env vars that matter everywhere
  (`MedVision_PLANNER_VERSION`, `MedVision_ACK_RELEASE`, `MedVision_DATA_DIR`, `HF_TOKEN`).
- Route map to the 10 sub-skills; cross-cutting references; safe operating rules (no GPU eval/training/
  downloads unless asked; never launch from private launcher dirs; treat `Data/`,`Results/` as data).
- Root references: `repo-provenance.md`, `repo-routing-metadata.json`, `troubleshooting.md` (cross-cutting),
  `concepts-and-glossary.md` (tasks/task names/dataset configs/units/metrics/CoT tags/file layout),
  `visualization-catalog.md` (28 figure entry points, reference-only), `model-roster.md` (name ↔ lmms_eval
  module ↔ opt-deps ↔ requirements file ↔ dockerfile ↔ parallelism ↔ hardware).
- Root scripts: `check_medvision_env.py` (imports/versions/CLI/medvision_ds/env vars/GPU/optional deps per
  workflow; `--repo-root`, `--json`; safe), `list_tasks.py` (task JSON → names, counts, dataset configs).

## Boundaries / cross-links
- `environment-setup` owns install/pins; `benchmark-evaluation` links to it for per-model requirements; `sft`/`rft`/`llm-judge-parsing`/`biomedparse-ablation` each own their *separate* env recipes but link back for shared pins.
- `dataset-and-tasks` owns task JSON + configs + downloads; `sft`/`rft`/`benchmark-evaluation` reference it for task lists.
- `results-parsing-and-metrics` owns metrics + summaries; `llm-judge-parsing` and `analysis` consume its outputs (`parsed/`, `llm-parsed_<judge>/`).
- `extending-models-and-tasks` is maintainer-facing; `benchmark-evaluation` links to it for "model not supported".
- Root `model-roster.md` is the single model table; sub-skills link to it rather than duplicating.
- Visualization: root `references/visualization-catalog.md` only.

## Review rubric (per sub-skill)
Identity (dir = frontmatter name = id), files on disk, scope coverage, depth (commands/flags/outputs/validation),
scripts bundled or justified, `references/troubleshooting.md` present with symptoms→cause→fix, evidence-backed
claims (verified via inspection env), self-contained (no links outside `skills/medvision/`, no repo paths as runtime
instructions), executable scripts have `--help`, frontmatter contract, no private paths.
